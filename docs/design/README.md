# Ondのマシン機能設計とロードマップ

この文書群は、Ondを、Kagura上のマシンを組み立て、内部を観測し、作品と仕様を一緒に配布できる開発環境へ育てるための設計案です。Ond 0.1.2へ収録する文書として整理し、その公開後に0.2.0の詳細設計と実装へ進む方針です。

ここに記すmachine runtime、GUI、device製品形式、`ond kagura-machine`と`ond kagura-device`は未実装の提案です。0.1.2への文書収録は、それらの機能の提供や、規範仕様・ABI・公開APIの確定を意味しません。0.2.0以降の版番号は機能配分案で、公開日や工数の約束ではありません。

## 設計上の方針

- ボードの実装はOndが提供し、その動作とパーツの接続規格は公開仕様として記述します。
- deviceは実装から独立した動作仕様を持ち、最小製品は仕様一式と一つ以上のhost向け実装で構成します。
- アプリとhost runtimeを独立して生成し、対応する別実装でも同じアプリを動かせることを検証します。
- 通常の最終成果物にも必要な仕様本文を残し、作品の流通が設計資料の分散保存につながるようにします。

個別binaryを共通runnerへ接続するnative module方式は第一候補です。具体的な接続ABIと採用方式は試作で判断し、未承認の第三者binaryを自動で実行する設計にはしません。

## 現在の機能との区別

現行のcompiler・CLI・LSPには、Windows x64とLinux x86_64（glibc）の開発・配布経路があります。一方、ロードマップで扱うmachine runtimeの複数OS対応は新しい機能です。0.5.0の計画は既存compilerのLinux対応を先送りする意味ではありません。

設計文書間のリンクは、このdirectory一式でたどれます。根拠として参照する規範仕様、実装ソース、過去のrelease記録はrepository側の資料です。配布archiveにそれらが含まれない場合はソースcheckoutを参照してください。隣接Kaguraへの相対リンクはKaguraのソースcheckoutがある場合の調査参照です。この区別は、将来のdevice・アプリ成果物で規範仕様本文を必須同梱する方針とは別のものです。
