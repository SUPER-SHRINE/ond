# ビルドと起動の手順

まず[最初のプログラム](first-program.md)に従って`ond init`を実行し、そのフォルダーで作業します。\
ここでは実行ファイルを作り、起動時に実行環境が行う準備を確認します。

## 実行の前に
ondはkagura規格のvm上で動く前提の言語です。\
ondとkaguraはC#と.NET、JavaとJVMに近い関係と言えます。

ondがコンパイル・リンクで生成するバイナリを実行するには[kagura vm規格](https://super-shrine.github.io/kagura/)を満たす仮想マシンが必要です。\
とてもシンプルな規格であるため自作することも難しくないでしょう。\
ぜひコンピュータサイエンスの理解を深めるために挑戦してみてください。\
(kagura vmを実装することでondが目指している事や、このドキュメントの内容をより鮮明に理解できるはずです)

## バイナリを作る

プロジェクトのフォルダーで次のコマンドを実行します。

```sh
ond compile .
ond link --project .
```

`ond compile .`はプログラムを検査し、リンクに渡す情報とパッケージごとの中間成果物を作ります。\
既定ではリンク用の情報を`.ond/target/build.ondbuild`へ、中間成果物を`.ond/target/ond-cache`へ保存します。

`ond link --project .`はその情報とプロジェクトの設定から、実行環境向けのバイナリとデバッグ情報を作ります。\
最初のプログラムの設定では、`.ond/target/a.bin`と`.ond/target/a.onddebug`に保存されます。\
これらのコマンドはファイルを作成するもので、バイナリの実行はしません。

設定に書く相対パスは、その設定を含む`ond.toml`があるフォルダーを基準に解決されます。\
コマンドの入出力は[コンパイル・リンク仕様](../../../specs/ond/build/commands.md)、保存先と設定項目は[ビルド設定](../../../specs/ond/build/packages.md#compileとlink設定)を参照してください。

## 外部の起動処理を使う

最初のプログラムは、外部ローダー（別の起動用プログラム）が起動を担当する設定です。\
この例ではROMを指定せず、RAMの先頭を4096、容量を65536バイトにしています。\
実際に使う機械のメモリ配置がこの設定に合っている必要があります。

スタック（関数呼び出し時に値などを一時的に置く作業領域）には8192バイトを予約します。\
`ond.toml`の`[link.exit]`で指定する`mode = "loop"`では、`main`が戻った後もCPUは動作を続け、Ondの終了処理内で制御を繰り返します。

外部ローダーは、バイナリのヘッダー（配置先や開始位置などの情報）を読み、実行形式の約束に従って内容をメモリへ準備します。\
この例ではROMを省略しているため、ヘッダーを含むバイナリ全体をRAMの先頭から同じ順序でコピーします。\
未初期化領域をゼロにし、スタックポインター（スタックの現在位置を示すCPU内の値）を設定してから、ヘッダーが示す実行開始位置（entry）へ制御を渡します。

OS（アプリの起動や機器利用を助ける基本ソフト）やローダーがこの準備を担う環境では、起動手順は通常利用者から見えません。\
Kaguraが定めるCPU命令とバスの約束だけでは、OSやローダー、メモリ配置は用意されません。\
実際に動かすときは、実機または仮想マシンのメモリ配置とローダーが、このプロジェクトの設定やバイナリ形式に対応していることを確かめてください。\
外部起動の形式とロード完了時の状態は[実行ファイル仕様](../../../specs/ond/artifacts.md#外部起動とセルフ起動)を参照してください。

## バイナリ自身に起動処理を含める

実行環境によっては、バイナリに起動処理を含めてROMから始める形式を使えます。\
次の例では、ROMの先頭を番地0、RAMの先頭を番地65536とし、それぞれ65536バイトの領域を用意します。

`ond.toml`にある`[project]`は残し、`[link]`とその子テーブルを次の内容に置き換えます。\
保存したら、上に示した2つのコマンドをもう一度実行します。

```toml
[link]
startup = "self"
stack-size = 8192
output = ".ond/target/a.bin"

[link.rom]
base = 0
size = 65536

[link.ram]
base = 65536
size = 65536

[link.exit]
mode = "loop"
```

この設定ではROMとRAMが重ならず、ROMの先頭番地が0になります。\
リンクした出力全体はROMの番地0から置かれ、実行環境がCPUをリセットすると、CPUは番地0から起動処理を実行します。\
この出力の先頭には、標準バイナリより前に起動処理が含まれます。\
CPUはその前置処理を命令として実行します。\
前置処理がローダーの役割を担い、未初期化領域をゼロにし、スタックポインターを設定してから、ヘッダーで指定された実行開始位置へ制御を移します。

この例にも画面へ文字を表示する処理はありません。\
画面に表示するには、対象機器の読み書き方法に合わせた処理が別に必要です。\
ROMやRAMの容量と配置が実際の機械に合うことを、利用する実行環境のメモリ配置と照らし合わせてください。\
設定と配置の条件は[ビルド設定](../../../specs/ond/build/packages.md#compileとlink設定)および[実行ファイル仕様](../../../specs/ond/artifacts.md#配置容量と出力範囲)に定義されています。
