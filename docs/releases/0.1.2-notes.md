# Ond 0.1.2（リリース準備中）

配布物を拡張側で検証するためのmanifest v1を追加します。
マシン機能の設計文書とロードマップも収録します。
資料は非規範の将来案であり、machine runtime、GUI、新コマンドの提供やABIの確定を意味しません。

## 配布物

- `ond-0.1.2-windows-x86_64.zip` と `.sha256`
- `ond-0.1.2-linux-x86_64.tar.gz` と `.sha256`
- `ond-0.1.2-manifest.json`

両OSのarchiveには、binary2件とREADME・CHANGELOG・LICENSEに加えて、
`docs/design/README.md`と関連する5文書を元の相対pathで収録します。
展開後は`docs/design/README.md`から読み始めてください。
規範仕様や実装ソース、隣接Kaguraへの調査参照は、設計文書の入口に記したとおりソースcheckoutで確認します。

manifestは`schemaVersion: 1`、repository、version、実Git commitと両targetを記録します。
各targetにはrustTarget、archiveのname／SHA-256／byte size、展開したLSPのname／SHA-256を含めます。
全階層のkeyは辞書順、targetsはtarget昇順、UTF-8（BOMなし）とLF末尾改行のcompact JSONです。
manifestはbinary由来の証拠のみを含み、sourceやcache、公開後に割り当てられるasset IDは含めません。

## リリース前の確認

WindowsとUbuntuのFull品質検査、Release smoke testを通した後に公開してください。
`tools/package-release.ps1 -Version 0.1.2`はnative archive、既存形式の`.sha256`と検証用descriptorを生成します。
両targetの出力を同じdirectoryへ集め、`tools/release-manifest.ps1 -Mode Generate -Version 0.1.2 -Commit <Git HEAD> -AssetDirectory <directory>`でmanifestを生成します。
`-Mode Verify`で同じ検証を再実行できます。descriptorはReleaseへ公開しません。

同じReleaseの再実行は、既存assetのSHA-256が候補と一致する場合のみ再利用します。
異なるassetがある場合は上書きせず停止し、欠けたassetのみを同じ候補から追加します。

main向けrelease PRをマージするだけでは公開されません。
公開時には別途、mainへ到達可能な確定commitへ`0.1.2` tagを作成・pushします。
tag起動のCIが両OSの検査・包装・manifest集約を通した後、GitHub Releaseと上記5 assetを公開します。
拡張側の正式採用は、公開後のtag／commit、archive／checksum／manifest、LSPの照合が成功してから行います。
