# Ond 0.2.0

0.2.0ではOnd v1のoperator宣言、raw memory access、method receiverの扱いを更新し、generic型の識別とLanguage Serverのproject診断を改善します。\
変更履歴は[CHANGELOG](../../CHANGELOG.md)、利用方法は[言語マニュアル](../manual/README.md)を参照してください。

## 互換性に関わる変更

### Operator宣言

operatorの型parameterはoperator宣言自身ではなく、receiver型へ記述します。\
既存の`Vec[T]`向け宣言は次の形へ移行してください。

```ond
// 変更前
operator[T] [](values: *Vec[T], index: u32) -> *T

// 変更後
operator (values: *Vec[T]) [](index: u32) -> *T
```

operator候補はoperandの静的型と、その型を所有するpackageに基づいて選ばれます。\
構文と選択規則は[Ond v1構文仕様](../../specs/ond/v1/syntax.md)を参照してください。

### Raw memory access

`load32`と`store32`を削除しました。\
従来の`load32(address: u32 | pointer) -> u32`および`store32(address: u32 | pointer, value: u32)`は、型付きpointerのindex accessへ移行します。

```ond
var status: u32 = registers[0]
registers[1] = command
```

`registers`は`*u32`として宣言し、indexは`u32`を使います。\
`pointer[index]`のaddressはpointerと`index * sizeof(T)`から計算されますが、allocation範囲やpointer寿命は検査されません。\
alignment違反やbusで許可されないaccessはfaultします。\
詳細は[Kagura v1 machine仕様](../../specs/ond/targets/kagura-v1/machine.md)を確認してください。

## 言語とcompilerの変更

- method呼び出しではreceiverに1段階の暗黙的なaddress取得または参照外しを適用
- 単純代入の配列bounds checkを各writeの直前に実施し、後続のcheckがtrapしても先行writeを保持
- 配列長の上限を`2^32 - 1`要素とし、Kaguraでは型のbyte sizeが`2^32 - 1`を超える配列layoutを拒否
- generic型のidentityとsymbolを安定化し、specialization cacheが具体化集合、型構造、生成定数、公開interfaceの変化を検出
- nil interfaceのmethod callでvtableの不在を検査
- pointer変数のmethod補完とpointer深度の型推論を修正
- LSPが依存packageのsourceを読み込み、未オープンfileを含むproject診断とfile-level indexを更新し、library／executableのrootを区別
- specのsemantic ID検証を追加
- machine／device管理の将来設計文書をGakudenへ移管

## 配布物

- `ond-0.2.0-windows-x86_64.zip` と `.sha256`
- `ond-0.2.0-linux-x86_64.tar.gz` と `.sha256`
- `ond-0.2.0-manifest.json`

対応する配布targetはWindows x86_64とLinux x86_64（glibc）です。\
検証環境はWindows x64、Ubuntu 22.04、Rust 1.91.1です。\
macOS、ARM64、Alpine/muslは検証対象ではありません。

archive内の`THIRD-PARTY-NOTICES.txt`と`COPYRIGHT-library.html`は元の相対pathで保持してください。\
拡張が`ond-lsp`をVSIXへ同梱する場合も、両noticeを変更せずbinaryと同じ場所へコピーします。
