# Ond Debug Metadata v1
<!-- ond-spec-id: debug-metadata/v1 -->

本書はlink前のDebugObjectとlink後のdebug sidecarを定義する。\
実行時ABIとmemory layoutはmetadataの有無によらず[target規範](../targets/kagura-v1/README.md)に従い、debug情報は独立sidecarで運ぶ。

## 1. 成果物
<!-- ond-spec-id: debug-metadata/artifacts -->

`ond link -o game.bin`は実行可能バイナリ、`game.onddebug`、test buildの場合は独立した`game.ondtest`を生成する。\
各build_idは[image識別子](../build/cache.md#公開識別子)と一致する。\
`-o -`はバイナリ全bytesだけをstdoutへ出力し、sidecarのfile出力は[CLI契約](../build/commands.md#ond-link)に従う。\
test caseの起動情報は[test sidecar](../build/test-build.md#起動情報と実行責務)を定義元とする。

JSONは[共通wire形式](../artifacts.md#json-wire形式)の閉schema、必須field、null、整数とenumの規則を適用し、次の型で表す。

| 型 | Field |
| --- | --- |
| DebugObject | `package: string`, `functions: ObjectFunctionDebug[]`, `ranges: ObjectDebugRange[]` |
| SourceLocation | `path: string`, `line: u32`, `column: u32` |
| ObjectFunctionDebug | `symbol: string`, `section: SectionKind`, `offset: u32`, `size: u32`, `frame_size: u32`, `return_address_offset: u32`, `source: SourceLocation or null`, `unwind: ObjectUnwindRow[]` |
| ObjectUnwindRow | `offset: u32`, `cfa_sp_offset: u32`, `return_address: ReturnAddressLocation` |
| ObjectDebugRange | `section: SectionKind`, `start: u32`, `end: u32`, `operation: DebugOperation`, `message: string or null`, `source: SourceLocation or null`, `function: string` |
| DebugInfo | `build_id: string`, `stack_bottom: u32`, `stack_top: u32`, `functions: FunctionDebug[]`, `ranges: DebugRange[]` |
| FunctionDebug | `symbol: string`, `address: u32`, `size: u32`, `frame_size: u32`, `return_address_offset: u32`, `source: SourceLocation or null`, `unwind: UnwindRow[]` |
| UnwindRow | `address: u32`, `cfa_sp_offset: u32`, `return_address: ReturnAddressLocation` |
| DebugRange | `start: u32`, `end: u32`, `operation: DebugOperation`, `message: string or null`, `source: SourceLocation or null`, `function: string` |

ReturnAddressLocationは`"LinkRegister"`または`{"StackOffset":u32}`とする。\
DebugOperationは`"Source"`、`"Call"`、`"MemoryRead"`、`"MemoryWrite"`、`"BoundsCheck"`、`"DivisionByZero"`、`"SignedDivisionOverflow"`、`"InvalidConversion"`、`"StackOverflow"`、`"ExplicitTrap"`のunit enumである。

## 2. sourceとfault range
<!-- ond-spec-id: debug-metadata/source-and-fault-range -->

PackageArtifact内のDebugObjectは同じartifactのObjectに所属し、packageは当該artifactとinterfaceの論理package pathに一致する。\
debug付きObjectを直接link入力へ与える場合も各DebugObjectの所属Objectを一意に対応づける。\
この所属対応は、診断用のObject.nameの値とは独立する。

link前のoffset、start、end、unwind.offsetはすべて所属Objectの該当section先頭からのbyte位置である。\
link後はヘッダ・セクション表・selfの前置起動処理を反映したObject sectionの最終先頭addressをchecked u32で加え、FunctionDebug.address、UnwindRow.address、DebugRange.start/endへ変換する。\
functions列はaddress昇順、ranges列はstart/endの辞書順とし、同じstart/endのrangeは入力Object列順、同Object内の入力range列順を保つ。

debug metadata v1のfunction・range・unwindは標準実行バイナリのTextだけを対象とする。\
selfの前置起動処理にはsource・unwind情報を生成しない。

| 対象 | 成立条件 |
| --- | --- |
| function | section=Text、同Objectの定義Function symbolと開始・sizeが一致、size>0、開始とsizeが4-byte aligned、checked終端がText memory_size以下 |
| function debug区間 | link後の半開区間[address,address+size)同士が重ならない |
| range | section=Text、start/endが4-byte aligned、0<=start<end<=Text memory_size |
| range.function | 同Objectの定義Function symbolを指し、rangeがそのsymbolの半開区間に含まれる |
| source | pathは非空のopaque表示識別子、line/columnは1以上。columnは行先頭からのUTF-8 byte数+1、LFで次行へ進み、tabは1byte |
| message | ExplicitTrapはstring（空も可）、他operationはnull |

この表のObjectとsymbolに依存する照合はlinkerが行う。\
range同士の包含・重複は許可する。\
rangeに対応するFunctionDebug recordの有無は、range成立条件に追加しない。\
source pathの実file存在は成立条件へ含めず、表示識別子として使う。

fault PCを含むrangeは`start <= PC < end`で選び、複数なら幅end-startが最小のもの、同幅なら最終ranges列で先のrecordを採用する。\
CPU faultのcodeと意味上のoperationの対応は[target fault表](../targets/kagura-v1/machine.md#faultと観測結果)に従う。\
ExplicitTrapのmessageはsourceのtrap理由literalを表し、他operationの表示文言はVMの選択とする。

## 3. functionとunwind
<!-- ond-spec-id: debug-metadata/function-and-unwind -->

function lookupは`address <= PC < address+size`を満たす唯一のFunctionDebugを選ぶ。\
そのfunctionのunwind列からaddress<=PCの最大addressを持つrowを選び、現在のSPにcfa_sp_offsetをchecked加算した値をcaller SPとする。\
LinkRegisterはr15の値、StackOffset(n)は現在SP+nの4byte little-endian値をcaller PCとし、return addressそのものを使う。

| 対象 | 成立条件 |
| --- | --- |
| unwind位置 | function先頭以上、終端以下の閉区間内、4-byte aligned、同function内で位置が一意 |
| 非空unwindの最初のrow | function先頭、cfa_sp_offset=0、return_address=LinkRegister |
| frame_sizeとcfa_sp_offset | 8-byteの倍数、0<=cfa_sp_offset<=frame_size |
| StackOffset(n) | nは4-byte aligned、checked n+4<=当該rowのcfa_sp_offset |
| return_address_offset | slotを持たない場合0、非zeroなら4-byte alignedかつchecked offset+4<=frame_size |

unwind列はaddress昇順に並べる。\
空unwindはそのfunctionからの復元rowを持たず、終端位置のrowはそのfunctionの半開区間lookupでは選ばれない。\
return_address_offsetはfull frame確保時の通常保存slotを示す参考fieldであり、復元には常に選択したrowを使う。

## 4. VM実装の責務
<!-- ond-spec-id: debug-metadata/vm-responsibilities -->

VMがsidecarを利用する場合、以下のlink後に観測可能な条件を検査する。

| 対象 | link後の静的検査 |
| --- | --- |
| DebugInfo | 閉schema、build_idが対象バイナリの全bytesから求めた識別子に一致、stack_topがヘッダのinitial_spに一致、stack_bottomが4-byte alignedでstack_top未満 |
| FunctionDebug | symbol非空、address/sizeが4-byte aligned、size>0、checked終端が標準実行バイナリのText実行時範囲内、functionsがaddress昇順で相互非overlap |
| DebugRange | function非空、start/endが4-byte aligned、start<end、同じimage Text section区間に包含、rangesがstart/end昇順 |
| SourceLocationとmessage | path非空、line/column>=1、operationごとのmessage型 |
| unwindとframe | 当該FunctionDebugの閉区間内、align4、重複なし・昇順、最初のrow・CFA/frame・StackOffset・return_address_offsetの数値条件 |

同値rangeのwire列順はlookup優先順位として保持する。\
link後のrange.functionに対応するFunctionDebug recordの存在は要求しない。\
link前のdebug不適合はlink error、link後sidecarの不適合はsidecar全体の使用拒否となる。\
metadataの有無、不適合、lookup結果はCPUの実行とfault結果を変更しない。

生成者はstack_bottomをlink設定のstack予約下端に一致させる。\
利用者が実行環境のRAM mapを照合する場合、stack予約範囲とRAM上のsection・標準バイナリコピー範囲の分離も確認できる。\
source位置、trap理由literal、実codeに対するframeとrow、およびstack_bottomとlink設定の意味的一致は生成者の規範義務である。\
VMの静的検査は元sourceやObject symbolを再構成せず、上記のschema・数値・区間条件を対象とする。

traceの各段階は現在のPCとSPから上記のfunction、row、callerを求める。\
次のいずれかに到達した場合、その段階でtraceを打ち切る。

- PCが4-byte alignedでない
- SPまたは復元CFAが[stack_bottom,stack_top]外
- StackOffset読取りの4byteが[stack_bottom,stack_top)外または不整列
- address計算がu32をoverflowする
- 同じ(PC,SP)を再訪する
- functionまたは適用rowが存在しない
- VMが明記するframe上限へ達する

trace用の読取りはstack RAM内だけで行い、MMIOへはアクセスしない。\
CPU faultのPCは実際にfaultした命令のPCとし、debug operationはそのfaultへ意味分類を加える。
