# numeric-runtimeの入力と期待値
<!-- ond-spec-id: conformance/cases/numeric-runtime -->

このcaseは動的演算のsource受理とMIR opcode/type/guardを検査する。\
外部契約はsourceの受理であり、MIR callbackはcompiler実装の回帰検査として区分する。

規範定義元: [CAST-02の定義元](../../language/v1/types.md#型同一性)、[CAST-03の定義元](../../language/v1/types.md#型同一性)、[FP-02の定義元](../../language/v1/expressions.md#floating-point-arithmetic)、[NUM-03の定義元](../../language/v1/expressions.md#integer-constant-arithmetic)、[NUM-04の定義元](../../language/v1/expressions.md#integer-arithmetic)、[NUM-05の定義元](../../language/v1/expressions.md#integer-arithmetic)。\
要件索引は[requirements](../requirements.md)、既存fixture宣言は[registry](../../../../crates/compiler-core/src/conformance/numeric/runtime.rs)を参照する。

共通のproject入力は`ond.toml`の`[project]`に`name = "test"`を置いた実行projectである。\
generated numeric/型境界のsourceはすべて`main.ond`の内容として読み、static表は各file名を入力欄に記す。

以下は移行時の既存case宣言に含まれる入力と仕様由来Expectedデータを記録したものであり、compilerを実行して得た結果の転記ではない。\
`accept`単独は受理を期待し、値の記載がある行はその型・値まで照合する。\
`implementation AST/MIR`は外部の受理・値期待と区分した実装回帰検査である。\
診断の原文は照合対象を示し、規範上の失敗結果はcompile errorとして読む。
