# static-evaluationの入力と期待値
<!-- ond-spec-id: conformance/cases/static-evaluation -->

Traceは実行したtagを左から10進連結する。\
callee→operand/argument順、代入前snapshotと左からの書込み、短絡・loop・return規則を各fixtureに適用して戻り値列を導く。\
入力は引数なしのmain.testであり、表の返値をMemoryVmで照合する。

規範定義元: [EVAL-02の定義元](../../language/v1/statements.md#静的成立条件)、[FLOW-02の定義元](../../language/v1/statements.md#静的成立条件)、[FLOW-03の定義元](../../language/v1/statements.md#静的成立条件)、[NAME-02の定義元](../../language/v1/names-and-scopes.md#scopeとshadowing)。\
要件索引は[requirements](../requirements.md)、既存fixture宣言は[registry](../../../../crates/compiler-core/src/test_vectors/evaluation.rs)を参照する。

共通のproject入力は`ond.toml`の`[project]`に`name = "test"`を置いた実行projectである。\
generated numeric/型境界のsourceはすべて`main.ond`の内容として読み、static表は各file名を入力欄に記す。

`accept`単独は受理を期待し、値の記載がある行はその型・値まで照合する。\
構文解釈は表のParse phaseで照合し、内部AST/MIRの構造検査は外部適合判定へ含めない。\
診断の原文は照合対象を示し、規範上の失敗結果はcompile errorとして読む。
